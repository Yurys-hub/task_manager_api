# Task Manager API

Асинхронный REST API для управления задачами и пользователями, разработанный на Python с использованием FastAPI и SQLAlchemy.

Проект создан для практики разработки REST API, работы с асинхронной базой данных, валидации входных данных и автоматизированного тестирования.

## Возможности

- Создание, получение, обновление и удаление задач (CRUD).
- Создание, получение и удаление пользователей.
- Получение списка задач с фильтрацией по статусу выполнения и поиском по названию или описанию.
- Получение пользователя вместе со списком его задач.
- Связь задач с пользователями через внешний ключ.
- Валидация входных данных с помощью Pydantic.
- Обработка ошибок `404 Not Found`, `409 Conflict` и `422 Unprocessable Entity`.
- Асинхронная работа с базой данных через SQLAlchemy.
- Автоматизированные тесты API с использованием pytest и HTTPX.

## Технологии

- Python 3.11+
- FastAPI
- Pydantic v2
- pydantic-settings
- SQLAlchemy (async)
- SQLite
- aiosqlite
- pytest
- HTTPX
- AnyIO

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/Yurys-hub/task_manager_api.git
cd task_manager_api
```

### 2. Создание виртуального окружения

```bash
python -m venv .venv
```

Активация в Windows:

```bash
.venv\Scripts\activate
```

Активация в Linux/macOS:

```bash
source .venv/bin/activate
```

### 3. Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

### 4. Настройка окружения (не обязательна)

Создай файл `.env` на основе `.env.example`.

Windows:

```bash
copy .env.example .env
```

Linux/macOS:

```bash
cp .env.example .env
```

Пример настроек:

```dotenv
DATABASE_URL=sqlite+aiosqlite:///./data/tasks.db
SQL_ECHO=false
```

- `DATABASE_URL` — URL подключения к базе данных.
- `SQL_ECHO` — включает или отключает вывод SQL-запросов в консоль.

Файл `.env` содержит локальные настройки и не должен добавляться в Git.

### 5. Запуск приложения

```bash
uvicorn main:app --reload
```

По умолчанию приложение будет доступно по адресу:

http://127.0.0.1:8000

Интерактивная документация API:

- Swagger UI: http://127.0.0.1:8000/docs
- ReDoc: http://127.0.0.1:8000/redoc

При запуске приложения создаются таблицы базы данных, если они ещё не существуют.

## API Endpoints

### Пользователи

| Метод     | Endpoint              | Описание                                      |
|-----------|-----------------------|-----------------------------------------------|
| `POST`    | `/users`              | Создать пользователя                          |
| `GET`     | `/users`              | Получить список пользователей                 |
| `GET`     | `/users/{user_id}`    | Получить пользователя вместе с его задачами   |
| `DELETE`  | `/users/{user_id}`    | Удалить пользователя вместе с его задачами    |

### Задачи

| Метод     | Endpoint              | Описание                                      |
|-----------|-----------------------|-----------------------------------------------|
| `POST`    | `/tasks`              | Создать задачу                                |
| `GET`     | `/tasks`              | Получить список задач с пользователями        |
| `GET`     | `/tasks/{task_id}`    | Получить задачу по ID c её полоьзователем     |
| `PATCH`   | `/tasks/{task_id}`    | Частично обновить задачу                      |
| `DELETE`  | `/tasks/{task_id}`    | Удалить задачу                                |

### Фильтрация задач

Эндпоинт `GET /tasks` поддерживает следующие query-параметры:

- `completed` — фильтрация по статусу выполнения (`true` или `false`).
- `name` — поиск по названию или описанию задачи.

Примеры:

```http
GET /tasks?completed=false
GET /tasks?name=report
GET /tasks?completed=true&name=report
```

### Пример создания задачи

Запрос:

```http
POST /tasks
Content-Type: application/json
```

```json
{
  "title": "Learn FastAPI",
  "description": "Practice asynchronous REST API development",
  "priority": 3,
  "user_id": 1
}
```

Поле `is_completed` необязательно и по умолчанию равно `false`.

При успешном создании возвращается `201 Created` с данными задачи.

### Частичное обновление задачи

Запрос:

```http
PATCH /tasks/1
Content-Type: application/json
```

```json
{
  "is_completed": true
}
```

Обновляются только переданные поля. Пропущенные поля остаются без изменений.

Поле `description` можно очистить, передав `null`. Для остальных полей действуют ограничения валидации, определённые в Pydantic-схемах.

## Обработка ошибок

API использует HTTP-статусы для обозначения результата запроса:

| Статус                        | Значение                                  |
|-------------------------------|-------------------------------------------|
| `201 Created`                 | Ресурс успешно создан                     |
| `200 OK`                      | Запрос успешно выполнен                   |
| `204 No Content`              | Ресурс успешно удалён                     |
| `404 Not Found`               | Пользователь или задача не найдены        |
| `409 Conflict`                | Конфликт уникальности имени пользователя  |
| `422 Unprocessable Entity`    | Входные данные не прошли валидацию        |

## Тестирование

Для тестирования используются pytest, HTTPX и AnyIO.

Тесты работают с отдельной базой SQLite в памяти (`:memory:`), поэтому не используют основную локальную базу приложения.

Перед тестами создаются необходимые таблицы и тестовые пользователи. После завершения фикстуры таблицы удаляются.

Запуск всех тестов:

```bash
python -m pytest
```

Тесты покрывают основные сценарии работы API, включая создание и удаление ресурсов, получение задач, валидацию входных данных, частичное обновление и обработку запросов к несуществующим ресурсам.
